# 运行边界、人工值守与飞书通知

适用于公开安装版 `v0.1.0-beta.1`。2026-11-26 根据安装版实际入口与程序闭包核查；本文补充发布页及包内指南。

## 适合怎样使用

直播洞察帮助 Windows 用户把自己有权访问和留存的抖音直播整理为本地录音、转写和可查询资料。需要让电脑和相关程序持续运行，并有人接手平台验证和异常排查。基础采集、本地转写和只读 MCP 不要求云模型密钥；可选云模型另有发送内容和服务商费用。

本工具不自动完成验证码，也不承诺绕过平台限制、持续在线、完整采集或恢复中断期间缺失的内容。macOS、Linux 适配不在首期公测范围。数据保存到使用者自己的电脑，磁盘空间和备份由使用者安排。

## 平台验证是已知值守事项

维护者于 2026-11-26 补充的既有部署经验是：通常运行约一到两周，可能需要人工打开平台页面处理一次验证或登录。**这只是该部署的经验，不是抖音官方固定周期，也不是其他账号和网络环境的可用性保证。** 可能更早、更晚或不出现。

遇到登录过期、验证页或访问限制时，应由使用者在专用浏览器中按页面提示处理。采集受限、失败或空数据也可能来自网络、接口变化或软件缺陷；不要未经排查就统一标记为“正常风控”。中断期间可能缺失资料，不能假定之后会自动补齐。

当前人工处理顺序：

1. 打开本地看板“设置 → 采集浏览器与平台登录”，先准备浏览器，再打开抖音登录页。
2. 在应用专用浏览器中，自行扫码登录或完成页面要求的验证。
3. 选择已登记的主播，执行“检查所选主播通道”；状态过旧时重新读取。
4. 回到“实时”页检查新鲜的探测结果和业务记录。浏览器已打开、通道可查询，都不能单独证明登录有效或采集已经恢复。用户主动关闭的采集、录音和转写不会因此自动开启。

## 建议连接飞书，但先了解当前覆盖范围

建议为长时间运行配置飞书通知，并主动确认测试消息送达。**当前 Beta 的通知还不完整，不能只等飞书消息来判断是否正常运行。** 也应定期查看看板和最新资料时间。

| 当前安装版已接入的通知 | 触发范围 |
| --- | --- |
| 开播与确认下播 | 对应采集流程确认的事件，带限频 |
| 采集进程退出、准备重启 | 由仍在运行的监控进程发现 |
| 采集连续快速退出、暂停重启 | 达到既有熔断条件 |
| 看门狗的 watch 子进程连续快速退出 | 达到既有熔断条件 |

**持续无法确认直播状态、登录验证待处理、浏览器反复掉线等情形，目前没有完整接入安装版远程告警。** 仓库中的旧 Health 探针没有随此 Beta 安装，也不会因为填了飞书地址就自动启用。程序或电脑整体停止、网络中断时，同一进程内的通知也可能无法发出。

这些消息会向使用者指定的飞书会话发送主播标识、可能的开播标题或故障摘要。此通知通道不发送录音和转写全文；飞书多维表格同步是另一条数据通道，不能混称。

## 当前 Beta 的手动配置方式

当前没有飞书设置页或“一键测试通知”按钮，以下步骤适合愿意编辑本地配置的试用者。只在自己的安装目录操作，不向 Issue 上传配置全文或机器人地址。

1. 正常停止直播洞察，备份 `<安装目录>/state/config.json`，编辑其中已有的 `feishu` 对象。
2. 仅接收事件通知时，保持多维表格写入开关 `enabled: false` 和 `backend: "dry_run"`，把**飞书群自定义机器人**地址填入 `webhook_url`。这里不是多维表格自动化 Webhook；不要为收告警而开启多维表格写入。
3. 机器人创建和安全配置见[飞书官方自定义机器人指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot?lang=zh-CN)。当前消息正文含“竞品监控”，可按组织策略使用匹配该正文的关键词过滤。当前通知发送器没有实现机器人签名字段；如果组织要求签名校验，这条直接通道暂不满足要求，不应为此关闭组织安全要求。
4. 另一种方式是保留空 `webhook_url`，使用飞书自建应用的 `app_id`、`app_secret` 和接收目标 `alert_chat_id` 或 `alert_open_id`；需要另行完成相应应用权限与接收对象配置。群机器人地址非空时优先走群机器人通道。
5. 保存合法 JSON 后，主动发送下方测试消息，确认指定会话实际收到，再正常启动程序。测试成功仅证明这次通知通道可用，不证明所有异常检测都已覆盖。

仅告警配置示意（将字段合并到已有 `feishu` 对象，保留其他配置；示意值不能直接发送）：

```json
{
  "enabled": false,
  "backend": "dry_run",
  "webhook_url": "<自己的飞书群自定义机器人地址>"
}
```

在 PowerShell 执行以下测试会主动向已配置会话发送一条通知。先将第一行改成自己的真实安装目录：

```powershell
$liveInsightHome = 'D:\LiveMonitor'
& "$liveInsightHome\runtime\python\python.exe" -B -c 'import pathlib,sys; p=pathlib.Path(sys.argv[1]); sys.path.insert(0,str(p/"app"/"scripts")); import notify; ok=notify.send_text("[竞品监控] 告警通道测试", key="manual-test", cooldown=0, config_path=str(p/"state"/"config.json")); print("已发送" if ok else "未发出，请检查本地配置和日志"); sys.exit(0 if ok else 1)' $liveInsightHome
```

安装版需要显式读取 `state/config.json`。不要直接复制源码开发入口 `python scripts/notify.py test`，它的默认配置路径不同。显示“已发送”后仍以接收会话确实收到消息为准。

## 怎样反馈才有助于定位

请在[问题反馈表](https://github.com/wgs2779294031/douyin-live-insight/issues/new/choose)说明版本、Windows 版本、异常时间、最近一次正常资料时间、脱敏错误提示，以及在专用浏览器中是否看到登录/验证要求。若已配置通知，可补充测试消息是否收到、当次异常是否收到提醒。没有确认过的原因请写“待排查”。

不要上传 Cookie、二维码、登录态、密钥、Webhook 地址、完整配置、真实录音或转写正文。飞书告警设置界面与持续通道异常提醒属于待讨论的功能补齐，目前尚未实现。
