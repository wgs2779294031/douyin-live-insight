# 运行边界、人工值守与飞书通知

本页描述 `v0.1.0-beta.2` 的通知设置与持续异常提醒，发布状态以 [Releases](https://github.com/wgs2779294031/douyin-live-insight/releases) 为准。旧 `v0.1.0-beta.1` 没有通知设置界面，也未完整接入持续异常提醒；请按下载包版本区分。

## 适合怎样使用

直播洞察帮助 Windows 用户把自己有权访问和留存的抖音直播整理为本地录音、转写和可查询资料。需要让电脑和相关程序持续运行，并有人接手平台验证和异常排查。基础采集、本地转写和只读 MCP 不要求云模型密钥；可选云模型另有发送内容和服务商费用。

本工具不自动完成验证码，也不承诺绕过平台限制、持续在线、完整采集或恢复中断期间缺失的内容。macOS、Linux 适配不在首期公测范围。数据保存到使用者自己的电脑，磁盘空间和备份由使用者安排。

## 平台验证是已知值守事项

维护者于 2026-11-26 补充的既有部署经验是：通常运行约一到两周，可能需要人工打开平台页面处理一次验证或登录。**这只是该部署的经验，不是抖音官方固定周期，也不是其他账号和网络环境的可用性保证。** 可能更早、更晚或不出现。

遇到登录过期、验证页或访问限制时，应由使用者在专用浏览器中按页面提示处理。采集受限、失败或空数据也可能来自网络、接口变化或软件缺陷；不要未经排查就统一标记为“正常风控”。中断期间可能缺失资料，不能假定之后会自动补齐。

当前人工处理顺序：

1. 打开本地看板“设置 → 采集浏览器与平台登录”，先准备浏览器，再打开抖音登录页。
2. 在应用专用浏览器中，自行扫码登录或完成页面要求的验证。
3. 选择已登记的主播，执行“检查所选主播通道”；状态过旧时重新读取。
4. 回到“实时”页检查新鲜的探测结果和业务记录。浏览器已打开、通道可查询，都不能单独证明登录有效或采集已经恢复。用户主动关闭的采集、录音和转写不会因此自动开启。

## 在设置页配置飞书通知

1. 在自己的飞书群中创建“自定义机器人”。创建方式及安全设置见[飞书官方指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot?lang=zh-CN)。请保管好机器人地址和签名密钥，不上传到 Issue 或公开截图。
2. 打开本地看板“设置 → 飞书异常通知”，选择“飞书群自定义机器人”，填写机器人地址。若机器人启用了签名校验，填写相应签名密钥。当前消息正文包含“竞品监控”，关键词过滤可按组织策略匹配该正文。
3. 勾选“启用飞书事件与异常通知”，点击“保存通知配置”。**保存只更新本地通知设置，不发送测试消息，也不证明消息已送达。** 页面不会回显已保存地址或密钥；留空保留已有值，填写新值才替换。
4. 点击“发送测试通知”，核对页面提示的接收目的地，再点击“确认发送测试通知”。它只向已保存的接收会话发送固定测试文本，不包含录音或转写全文。请到该飞书会话确认实际收到。
5. 如果结果未确认，先检查接收会话，再重新读取通知状态，不连续重复点击。程序不会自动重发用户的测试请求。测试成功仅证明这次通道可用，不能代替长期运行检查。

需要停用时，取消启用并保存即可保留通知配置。需要清除时，连续两次确认“停用并清除通知配置”：它停用事件通知，清除通知专用地址和签名密钥，**不会修改多维表格同步配置，也不会回退继续发送旧通知**。单独清除签名密钥可勾选对应选项后保存；组织要求签名时应同时维护机器人设置，不能为发送而关闭组织安全要求。

如本机已有完整飞书应用凭据和接收目标，可选择“沿用已有飞书应用接收配置”；本页不新增或编辑该应用的权限。检测到旧版通知配置时，会显示来源提示；保存后使用独立的通知设置。新版事件通知与飞书多维表格同步分开，开启通知不要求开启多维表格写入。

## 哪些异常会提醒

| 通知 | 范围与条件 |
| --- | --- |
| 开播与确认下播 | 对应采集流程确认的事件，带限频 |
| 采集进程退出、准备重启 | 由仍在运行的监控进程发现 |
| 采集连续快速退出、暂停重启 | 达到既有熔断条件 |
| 看门狗的 watch 子进程连续快速退出 | 达到既有熔断条件 |
| 持续无法确认直播状态 | 仅对启用监控的目标，经过初启宽限、持续未知时间和多轮阈值，并结合近期有效业务证据抑制误报 |
| 通道恢复 | 此前已成功发送持续异常提醒，之后获得新鲜、有效的直播或未播探测证据；人工停用不发恢复通知 |

持续异常提醒会请使用者检查登录或验证、网络及平台页面，不会断言“这一定是风控”。当前默认初启宽限 5 分钟；连续未知至少 10 分钟且不少于 3 轮，并且近 3 分钟没有语义有效业务数据时才达到提醒条件。有效业务新记录可抑制误报，不能单独证明账号登录或探测通道恢复。

同一个异常事件发送成功后不重复刷屏。发送失败会有限重试；恢复通知需要新鲜的有效探测证据，不表示中断期间的资料已补齐。状态在当前监控进程生命周期内积累，重启后重新观察门槛，不承诺跨重启的全局去重。

这些消息会向使用者指定的飞书会话发送主播标识、可能的开播标题或故障摘要，此事件通知通道不发送录音和转写全文。程序、电脑或网络整体停止时，进程内通知可能无法发出；外部整机离线心跳不在此版本实现范围，仍需定期查看看板和最新资料时间。

## 其他通道只提供接入思路

目前只内置飞书事件通知，不包含企业微信、钉钉、邮件或其他平台的现成发送功能。设置页不接受把这些平台的地址填作飞书机器人地址。

有开发能力的使用者可以在自己的分支中研究适配其他平台的官方通知 API：复用“事件判断”与“消息发送”分开的思路，按目标平台要求自行实现身份校验、收件范围、发送结果、去重和失败处理，并使用合成事件验证。也可以自行选择独立监控工具，从外部检查程序或电脑是否仍在线；这和应用内部的采集异常提醒属于不同覆盖范围。

以上是接入思路，不是本项目已实现或已验证的通道。凭据由使用者自行在自己的环境管理，无需提供给项目维护者。具体问题可以先提交功能建议讨论，不承诺收到建议后立即实现。

## 怎样反馈才有助于定位

请在[问题反馈表](https://github.com/wgs2779294031/douyin-live-insight/issues/new/choose)说明版本、Windows 版本、异常时间、最近一次正常资料时间、脱敏错误提示，以及在专用浏览器中是否看到登录或验证要求。若已配置通知，可补充测试消息是否收到、当次异常是否收到提醒、人工处理后是否收到恢复通知。没有确认过的原因请写“待排查”。

不要上传 Cookie、二维码、登录态、密钥、Webhook 地址、完整配置、真实录音或转写正文。
